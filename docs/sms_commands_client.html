SPS SMS Commands

Get Status

All command replies and alerts are queued and retried after network recovery or the SMS-send cooldown. Each message is tracked separately, so an accepted first part is not deliberately repeated when a later part fails. Command actions are not repeated by message retries. The queue holds 24 messages in RAM; incoming command polling pauses when fewer than four reply slots remain. Pending messages do not survive a reboot. See SMS reply reliability.

Get Hardware Info

Send gethwinfo (case-insensitive, no arguments). One SMS gives a compact hardware/runtime summary.

nRF54L15 FW=1.0.0+0
CPU avg=3.2%
Uptime=0d 1h 48m
Stack peak%=Main:28 Log:44 Max:78
Heap KiB=2 used/4 free
Threads=7 Reset=Pin
SMS queue=2/24

Example readings only. CPU avg is average busy CPU since boot. Uptime is days, hours and minutes. Stack peak% shows the highest stack usage since boot for Main (application), Log (logging), and Max (highest thread percentage). Lower percentages mean more stack headroom. Heap KiB shows allocator memory used/free in whole KiB (1024 bytes), rounded down; free is not total unused RAM. Threads counts operating-system threads. Reset names the recorded boot cause: Pin, Software, Watchdog, Lockup, Debug, Other, Unknown or N/A. SMS queue is pending outgoing messages / capacity before this reply is added. N/A means unavailable. One SMS, maximum 160 characters, using the shared retry queue. Detailed interrupt-stack readings remain in RTT logs.

Get OTA Info

Send getotainfo (case-insensitive, no arguments). One SMS reports firmware-update status and persistent recovery history.

OTA
Run=Internal
From=Backup B
Backup=Ready
Health=OK/60s
Boots=12 WDT=3
Streak=0/3
Recoveries=1
Last=Watchdog
Update=Idle

Run is always Internal. From is Initial, Updated, Backup B or Unknown: Backup B identifies firmware restored from the recovery copy; Updated means a different image was observed through OTA or SWD. Backup is Ready, None or Bad, checked again when this command runs. Health is Wait/60s or OK/60s after one minute of main-loop progress. Boots counts application starts; WDT counts hardware or Zephyr task-watchdog resets. Streak is consecutive watchdog failures out of three. Recoveries counts completed restorations, and Last names the latest reason (Watchdog, Image or None). History remains after the streak clears. Update is Idle, Checking, Manifest, Download, Stage, Verify, Pending, Failed or Recovery.

Counts start with the updated bootloader and persist in external flash. Recovery housekeeping reboots are excluded from Boots. This is a status query; it does not start an update. Older firmware without this command cannot answer it after rollback. See FOTA setup for details.

Get Cellular Info

Send getcellularinfo (case-insensitive, no arguments). One SMS shows the main cellular information, including latitude and longitude.

Send SMSExample response

Network=Roaming
Signal=-63 dBm
SIM=Ready
IMEI=863866074042672
ICCID=89882280666242663460
Lat=42.056050

Carrier is the mobile operator. Network is Connected, Roaming, Searching, Offline, Denied or Unknown; both Connected and Roaming mean successful registration. Signal is in dBm: a less negative number is stronger. SIM is Ready, Locked or Unknown. IMEI identifies the modem; ICCID identifies the SIM card. Carrier names are limited to 16 characters to keep one SMS.

Lat and Lon are a cellular location estimate in decimal degrees, not a GPS fix. Both fields always appear. Unknown means a location was unavailable; zero or an old position is never substituted. An active data connection is needed to request the location, which can take up to 30 seconds.

The command refreshes cellular information without changing network settings. Detailed modem responses remain in firmware logs for diagnostics. See cellular diagnostics.

On BL54L15, calibration and device settings are saved in external flash and read back for verification. Internal settings storage is unused, with no automatic migration. See external flash storage.

Heartbeat Interval

The default is 30 days when no valid saved setting exists. A valid saved interval, including zero (disabled), takes precedence.

The interval is measured in uptime days, supports three decimal places, and is saved across restarts. Use zero to disable periodic heartbeats. The uptime counter and heartbeat schedule restart when the SPS reboots.

Utility Power Lost — Fuse Probably Blown

When input AC is detected on FUSE_DETECTION (P1.12), but all socket metering channels are below 50 V for three consecutive network-ready alert polls, the utility-loss message includes a probable fuse fault. The optocoupler input is active-low and sampled over up to 40 ms to detect AC pulses. This assumes the optocoupler measures before the fuse and the meters measure after it.

Output
Alert=Utility power lost - fuse probably blown
Utility=OFF
Device=0110
Outlet=1111
RSL=-101
Batt=4.44
Lat=42.027998
Lon=-91.631620
FW=1.0.0+0
HBD=0.000

No incoming command is required and no outlet report follows this alert. Without detected input AC, the normal utility-loss alert remains. If input AC returns during an outage but socket voltage does not, this alert follows after confirmation. A metering fault or another downstream interruption can also cause these symptoms. Failed sends are retried; a successful fuse alert is sent once until socket voltage returns, when the existing restoration alert and outlet report follow.

Device Power Alerts

The monitor averages five active-power readings independently per outlet, uses the universal on/off thresholds, and confirms a change for three consecutive averaged readings before sending an alert. A connected load at startup is also reported after confirmation; it is not silently treated as an initial baseline. Negative active-power readings are reported as zero. Intentional relay OFF/ON and reboot commands do not generate load alerts: monitoring settles quietly after actual relay changes. Later load changes on an already-enabled relay are reported normally. An ON command on an already-ON relay does not reset monitoring. This applies to any appliance.

Firmware Updates

Send ota=1.0.1 (version 1.0.1+0), or include the build number, for example ota=1.0.1+2. The device downloads the configured public release manifest and named signed binary over cellular HTTPS. The requested version must match both. FW reports use this same version from the build.

OTA 1.0.1+0 accepted; checking manifest
OTA 1.0.1+0 verified; rebooting to install

These are separate progress replies. The device verifies the complete image and its signature, waits for the modem to accept the completion SMS, then reboots to install. Failed downloads or checks return an ERR OTA reply without requesting an install reboot. Modem acceptance does not prove delivery.

Use getotainfo for progress. Only one update can run, and the current firmware must show Health=OK/60s. A stages the update; B keeps the previous healthy firmware for recovery. Settings retain their partition.

The repository URL must first be configured; otherwise the reply is ERR OTA URL not configured. See HTTP OTA for publishing the two standard DFU files, configuration and first-unit testing, and FOTA setup for recovery/build details. BLE is future work.
