Get Cellular Info

Send getcellularinfo (case-insensitive, no arguments). One SMS shows the main cellular information, including latitude and longitude.

Send SMSExample response
getcellularinfo
Cellular
Carrier=AT&T
Network=Roaming
Signal=-63 dBm
SIM=Ready
IMEI=863866074042672
ICCID=89882280666242663460
Lat=42.056050
Lon=-91.654126

Carrier is the mobile operator. Network is Connected, Roaming, Searching, Offline, Denied or Unknown; both Connected and Roaming mean successful registration. Signal is in dBm: a less negative number is stronger. SIM is Ready, Locked or Unknown. IMEI identifies the modem; ICCID identifies the SIM card. Carrier names are limited to 16 characters to keep one SMS.

Lat and Lon are a cellular location estimate in decimal degrees, not a GPS fix. Both fields always appear. Unknown means a location was unavailable; zero or an old position is never substituted. An active data connection is needed to request the location, which can take up to 30 seconds.

The command refreshes cellular information without changing network settings. Detailed modem responses remain in firmware logs for diagnostics. See cellular diagnostics.

On BL54L15, calibration and device settings are saved in external flash and read back for verification. Internal settings storage is unused, with no automatic migration. See external flash storage.

Heartbeat Interval

The default is 30 days when no valid saved setting exists. A valid saved interval, including zero (disabled), takes precedence.

The interval is measured in uptime days, supports three decimal places, and is saved across restarts. Use zero to disable periodic heartbeats. The uptime counter and heartbeat schedule restart when the SPS reboots.

Send SMSOutput
SetHeartbeatDays=30.43
 
OK SetHeartbeatDays=30.430
 
SetHeartbeatDays=0
 
OK SetHeartbeatDays=0.000

Device Power Detection Thresholds

These universal settings apply to all four outlets and are saved across restarts. At startup, power below 1.000 W is off and power at or above 1.000 W is on. During operation, power must rise above the on threshold to change on or fall below the off threshold to change off.

Utility Power Lost — Fuse Probably Blown

When input AC is detected on FUSE_DETECTION (P1.12), but all socket metering channels are below 50 V for three consecutive network-ready alert polls, the utility-loss message includes a probable fuse fault. The optocoupler input is active-low and sampled over up to 40 ms to detect AC pulses. This assumes the optocoupler measures before the fuse and the meters measure after it.

Output
Alert=Utility power lost - fuse probably blown
Utility=OFF
Device=0110
Outlet=1111
RSL=-101
Batt=4.44
Lat=42.027998
Lon=-91.631620
FW=001.00
HBD=0.000

No incoming command is required and no outlet report follows this alert. Without detected input AC, the normal utility-loss alert remains. If input AC returns during an outage but socket voltage does not, this alert follows after confirmation. A metering fault or another downstream interruption can also cause these symptoms. Failed sends are retried; a successful fuse alert is sent once until socket voltage returns, when the existing restoration alert and outlet report follow.

Device Power Alerts

The monitor averages five active-power readings independently per outlet, uses the universal on/off thresholds, and confirms a change for three consecutive averaged readings before sending an alert. Startup uses 1.000 W and initializes silently. Negative active-power readings are reported as zero. Intentional outlet-off periods reset the monitoring baseline and do not generate these alerts.

Output
Alert=Device power lost
Outlet=3
3=119.340V,0.000A,0.000W
 
Alert=Device power restored
Outlet=3
3=119.340V,0.035A,4.262W
